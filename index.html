Merging fine-tuned LLMs without retraining via decoder-aware surgery preserves performance

DARTS: Decoder-Aware Representation Tuning via Surgery for Model Merging

Aaryan Ajay Sharma, Sai Nishanth Padala, Seganrasan Subramanian · cs.LG · 8/10 signal

Use decoder‑aware adapter surgery to merge fine‑tuned LLMs and retain near‑original task performance without full retraining.

The paper tackles the practical bottleneck of serving many task‑specific LLMs by proposing a way to fuse them into a single model without the usual costly retraining. Existing merging techniques either degrade performance or require full fine‑tuning, which defeats the purpose of rapid deployment.

DARTS (Decoder-Aware Representation Tuning via Surgery) isolates the decoder layers that drive task‑specific outputs, learns lightweight linear adapters that align hidden representations across models, and applies these adapters while leaving the bulk of the pretrained weights untouched. The method is applied to a small validation set to calibrate the adapters, yielding a merged model ready for inference.

The whole edition, one paper

The problem
Practitioners need to serve multiple fine‑tuned LLMs for different downstream tasks, but maintaining separate models inflates memory, latency, and operational complexity. Naïve weight averaging or ensembling either harms accuracy or multiplies inference cost, and full retraining of a multi‑task model is expensive.
How it works
DARTS first identifies decoder layers that are most responsible for task‑specific logits. It then inserts a learned linear transform (the "surgery") between the shared encoder output and each decoder, aligning the representation space of the individual models. These transforms are optimized on a modest validation set (≈500 examples per task) while the rest of the network remains frozen, effectively stitching together the strengths of each specialist.
What they measured
Merging three T5‑Base models (sentiment, QA, summarization) yielded an average performance drop of only 1.2% relative to the best single model, versus a 5.8% drop for naïve weight averaging. Inference latency remained unchanged, and the merged model used ~30% less GPU memory than running an ensemble of the three originals.
Where it breaks
The technique assumes compatible tokenizers and encoder‑decoder architectures; it does not generalize to decoder‑only models like GPT. Alignment via a single linear map can fail when tasks induce highly divergent hidden spaces, and scaling beyond four models shows diminishing returns without additional regularization.
What this unlocks
Practitioners can now deploy a single LLM that handles several downstream tasks with near‑individual accuracy, cutting GPU memory and simplifying service orchestration. The approach also enables rapid prototyping of new task combinations without full fine‑tuning cycles.
